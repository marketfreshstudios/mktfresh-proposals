# Stripe Connect test setup

MarketFresh’s existing Stripe account is the platform. Workspace 1 keeps billing directly through its existing `STRIPE_SECRET_KEY` and `STRIPE_WEBHOOK_SECRET`. Every other workspace authorizes its own existing Stripe account. Stripe recommends Connect onboarding and Accounts v2 for creating and onboarding managed connected accounts. Standard-account OAuth fits Yeswell’s requirement to let a merchant grant access to a Stripe account it already uses and retain its full Dashboard. [Stripe Standard accounts](https://docs.stripe.com/connect/standard-accounts) · [Stripe OAuth](https://docs.stripe.com/connect/oauth-standard-accounts) · [Stripe Accounts v2](https://docs.stripe.com/connect/accounts-v2)

## Before deploy

Apply [the account routing migration](../supabase/migrations/20261109210000_stripe_connect_account_routing.sql). It adds a unique index on the routing digest in the existing service-only credential table. It adds no rows, grants, or policies. The prior `replace_provider_credential` migration must already be applied.

## Dashboard and deployment

1. Open MarketFresh’s Stripe Dashboard and select the sandbox or test environment. In **Connect**, start platform setup if it is incomplete. Complete the platform profile as a SaaS platform for businesses that take their own payments. Yeswell creates direct charges on each merchant’s own Stripe account. The merchant retains its full Stripe Dashboard.
2. In **Settings → Connect settings**, set the platform branding display name to **Yeswell** and upload [the Yeswell icon](../design/brand/yeswell/png/yeswell-app-icon-512.png). Use Ink `#13303A` and Clay `#C2602F` where Stripe offers brand colors. Enable OAuth for accounts with the Stripe Dashboard and copy the test Connect client ID to `STRIPE_CONNECT_CLIENT_ID`. Set the full test secret key from the same MarketFresh platform sandbox as Sensitive `STRIPE_CONNECT_SECRET_KEY`. Keep the existing direct Stripe credentials in place for workspace 1. Stripe uses the registered platform brand on its authorization page. [Configure Stripe OAuth](https://docs.stripe.com/connect/oauth-standard-accounts)
3. In **Connect settings → Redirects**, register `https://proposals.mktfresh.com/api/connections/stripe/callback` for the current deployment, assuming its `APP_URL` still uses that origin. The exact URL is `<APP_URL origin>/api/connections/stripe/callback`. To test Preview, use a fixed HTTPS preview origin, register its exact callback URL separately, and set its `APP_URL` or `STRIPE_CONNECT_REDIRECT_URI` to match. Start Connect from that same origin. OAuth returns to this callback and Yeswell opens `/studio/connections/stripe`. The Account Links refresh URL does not apply to this flow. [OAuth redirects](https://docs.stripe.com/connect/oauth-reference)
4. In **Workbench → Webhooks → Add endpoint**, choose **Connected accounts** and **Snapshot** events. Use API version `2024-06-20` and endpoint `https://proposals.mktfresh.com/api/webhooks/stripe/connect` (or the fixed preview origin for Preview). Subscribe to `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `checkout.session.async_payment_failed`, `invoice.paid`, `invoice.payment_failed`, and `account.application.deauthorized`. Store that endpoint’s signing secret as Sensitive `STRIPE_CONNECT_WEBHOOK_SECRET`. Keep the existing workspace 1 webhook endpoint and signing secret. [Connect webhooks](https://docs.stripe.com/connect/webhooks)
5. Keep `BILLING_MODE=test` and the existing Sensitive `INTEGRATION_ENCRYPTION_KEY`. Set the new variables only for deployments that will run the sandbox pilot. Use test keys and synthetic records.
6. In a workspace other than MarketFresh, open **Studio → Connections → Stripe**, choose **Test mode**, and select **Connect Stripe**. Authorize a different existing test account. Confirm that the setup page synced test prices with lookup keys, matched customers by exact unique email, and shows Billing events as **Configured**. Complete a synthetic recurring Checkout to verify the endpoint and see **Receiving**. For MarketFresh itself, use the existing direct Stripe setup.

Yeswell encrypts the connected account ID and mode. It discards the OAuth access and refresh tokens and scopes Stripe API calls with the platform key and the `Stripe-Account` header. Disconnect revokes access in Stripe. Existing subscriptions remain in the merchant account. To protect existing billing references, reconnect the same account in the same workspace. Duplicate customer email matches are left for staff review.
