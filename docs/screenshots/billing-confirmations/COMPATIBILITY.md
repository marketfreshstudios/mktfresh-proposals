# Billing confirmation review

The gallery includes **112 application/email captures**. Checkout card-saving and payment modes, the returning/finishing state, the bounded timeout, verified completion, yearly billing and staff waiting/completed states cover **375/768/1440 in light and dark**. The Emails list and both new template editors also cover all three widths/themes. Four real mock-transport emails (setup/subscription, client/sender) include portable HTML and generated plain text, plus 375/600 light/dark browser renders. All records, provider responses, cards and deliveries are synthetic.

Jonathan's new confirmation requirements take precedence over the original frames. The layouts retain the reading column, billing item list, separate one-time invoicing, staff cards and shared controls. Contextual design exports: [client billing 1e](../client-completion/reference-1e-light.png), [completed client view 1f](../client-completion/reference-1f-light.png), [staff record 3a](../phase4/reference-3a-light.png). These frames provide layout context; they do not contain the new verified receipt or return timeout.

Checks cover a query string without a verified receipt, prompt webhook jobs, full and partial Checkout completion, the 60-second polling limit, no polling after completion/timeout, card brand/last four, known/unknown next dates, yearly rates, staff test-dashboard links, both confirmation recipients, and protection against duplicate subscriptions/notifications. Public polling has a separate read-only, signed-proposal/password-checked state endpoint and never records views or changes proposal revisions.

Email renders use the base layout introduced in PR #35: maximum 600px, system fonts, inline/table fallbacks, one managed primary button and a workspace/sender footer. Verified product names/rates/card/date are protected receipt data, appended as escaped literal text; template edits cannot omit or reinterpret them. The explicitly requested billing receipt is an exception to price-free default proposal/reminder emails. Native Gmail/Apple Mail/Outlook screenshots remain unverified; Jonathan selected rendered previews in the email-template PR. No real email was sent.

Reproduce with `npx playwright test e2e/billing-confirmations.spec.ts e2e/emails.spec.ts`, then `node --import tsx scripts/package-billing-confirmations.ts`. The browser test uses real application services and a mock Stripe transport, plus an accelerated browser clock for the timeout. No environment file or provider credential is needed.
